## 0.2.2 黑帧诊断与绘制状态修复（竖屏短录已通过）

用户反馈 0.2.1 成片首帧正常、随后黑屏。提供日志来自 iPhone 16（iPhone17,3）/iOS 26.6.2，两次前置录制约 2.4/2.75 秒，均生成 720×1280、up 方向的文件并保存成功。日志没有源视频参数、是否跳过转码、逐帧像素或绘制状态，所以不能单凭 export.success 确认黑帧起因。

新增 export.source / passthrough / frame / encoded / verify.frame / verify.summary 日志，只含尺寸、帧数、时间戳和采样平均亮度，不保存图像像素。对编码文件前段最多 30 帧作采样核对；输入渲染有画面、编码文件却连续黑帧时阻止合成/保存。采样检查不能证明整段画面或音画同步正常，黑暗场景与后段故障仍需实际回放判断。原片直通分支单独记录源帧采样。

17 项自动测试通过，其中模拟编码器改变 GL 状态，验证每帧重新绑定；模拟首帧正常随后黑屏，确认不能被当作合成成功。仍需同一 iPhone 录制约 3–5 秒、查看实际画面；若失败，使用新增帧级日志定位，避免盲目改版。

## 实现与依据

提词采用 camera 内嵌套 cover-view 的可见行窗口，只更新当前约 5 行，80ms 更新一次位移。速度单位为像素/秒；文字到末尾停止，录像独立继续。录像使用 `CameraContext.startRecord` / `stopRecord`，相册使用 `wx.saveVideoToPhotosAlbum`。先拍摄、预览，再由用户点击保存，不自动上传。

- [微信官方 API 类型定义（相机与相册接口）](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)
- [camera 组件](https://developers.weixin.qq.com/miniprogram/dev/component/camera.html)
- [cover-view 组件](https://developers.weixin.qq.com/miniprogram/dev/component/cover-view.html)
- [开始录像](https://developers.weixin.qq.com/miniprogram/dev/api/media/camera/CameraContext.startRecord.html)
- [保存视频到相册](https://developers.weixin.qq.com/miniprogram/dev/api/media/video/wx.saveVideoToPhotosAlbum.html)

相机覆盖层、iOS 原生组件样式、镜头切换 initdone 时机，以及隐私授权弹窗必须以真实微信版本实测结果为准。此版专用于确认这条技术路线，不宣称已达到正式商用稳定性。
